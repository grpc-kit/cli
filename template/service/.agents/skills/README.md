# 服务技能

本目录保存随服务仓库一起维护的项目级技能。任务与某个技能匹配时，先完整阅读对应的 `SKILL.md`，再按需读取其引用的资源。

## 创建技能

每个技能使用独立目录：

```text
.agents/skills/<skill-name>/SKILL.md
```

`SKILL.md` 必须以 YAML frontmatter 开头，并包含：

- `name`：与父目录同名，仅使用小写字母、数字和单连字符。
- `description`：简要说明技能完成什么工作，以及应在什么情况下使用。

正文应提供本服务可直接执行的步骤。只有确有需要时才增加 `scripts/`、`references/` 或 `assets/`；从 `SKILL.md` 出发使用相对路径引用这些资源。

## 技能范围

服务技能与 `scripts/skills` 中的共享技能相互独立。使用服务技能不需要运行 `make skills`，也不应自动修改共享技能 submodule。

部分客户端会原生发现 `.agents/skills/`，其他客户端则通过 `AGENTS.md` 中的索引按文件读取。新增或删除技能时，请同步维护 `AGENTS.md` 的简短索引。避免在不同作用域创建同名技能；发生重名时，应明确使用仓库内的具体文件路径。

## 模板打包限制

本目录同时是 grpc-kit CLI 的嵌入式模板资源。不要在模板技能子树中添加隐藏文件、以下划线开头的文件、符号链接或独立 `go.mod`，否则文件可能无法可靠地进入发布产物。生成服务后由业务维护者新增的资源不受此模板打包限制。
