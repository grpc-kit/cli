# gRPC Kit

主要基于以下几个核心类库实现：

- [grpc](https://github.com/protocolbuffers/protobuf-go)
- [grpc-gateway](https://github.com/grpc-ecosystem/grpc-gateway)

## 简要概述

快速生成微服务模版，为同一产品提供统一的治理方式，提高多人协作效率

## 迁移已有项目

`project migrate` 用于把旧项目中由 grpc-kit-cli 管理的文件迁移到 `pkg v0.5.0` 兼容版本。默认只预览计划和 diff，不写文件：

```shell
grpc-kit-cli project migrate ./service
```

确认项目位于 clean Git 工作树、diff 符合预期，并完成输出中的人工迁移项后，可使用正式稳定版 CLI 应用托管文件变更：

```shell
grpc-kit-cli project migrate ./service --apply
```

命令只会更新首行带有完整 `Code generated by "grpc-kit-cli/...". DO NOT EDIT.` 标记、且存在内嵌兼容资产的已有文件；不会修改 `go.mod`、业务源码或其他用户管理文件，也不会创建、删除或重命名文件。`Manual action` 表示仍需人工完成的 Go 版本、pkg、logrus/slog 或 context API 迁移，因此“托管文件已迁移”不等于“项目已通过编译验证”。根级 `upgrade`/`update` 不用于项目迁移；未来 CLI 自身更新保留 `self update` 语义。

## 生成代码并运行（本机方式）

### 创建应用模版

```shell
mkdir -p $GOPATH/src/github.com/opsaid
cd $GOPATH/src/github.com/opsaid

grpc-kit-cli new -t service -p opsaid -s test1
```

### 下载依赖的环境

```shell
make protoc
make protoc-gen-go
make protoc-gen-go-grpc
make protoc-gen-grpc-gateway
make protoc-gen-openapiv2
```

### 运行应用代码

```shell
make run
```

## 生成代码并运行（容器方式）

### 创建应用模版

```shell
docker run \
    --rm \
    -v $(pwd):/usr/local/src \
    -w /usr/local/src \
    ccr.ccs.tencentyun.com/grpc-kit/cli:0.3.5 \
    grpc-kit-cli new -t service -p opsaid -s test1
```

### 运行应用代码

```shell
docker run -i -t --rm \
    -v $GOPATH/pkg:/go/pkg \
    -v $(pwd):/usr/local/src \
    -w /usr/local/src \
    --network host \
    ccr.ccs.tencentyun.com/grpc-kit/cli:0.3.5 \
    make run
```
